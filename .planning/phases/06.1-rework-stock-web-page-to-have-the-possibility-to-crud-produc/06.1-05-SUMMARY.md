## Decisions Made

**1. SKU truncation rule (reverse-engineered from the plan's pinned examples).**
The plan's `<interfaces>` block describes `skuToken` in prose as "uppercases, strips diacritics, removes non-alphanumerics, then truncates to maxLength" — which reads as plain left-to-right substring truncation. But its own three pinned examples are only self-consistent under a different rule:
- `generateSku('T-Shirt', 'M', 'Black')` → `'TSHIRT-M-BLK'` (plain truncation would give `'BLA'`, not `'BLK'`)
- `generateSku('T-Shirt', 'XL', null)` → `'TSHIRT-XL'` (no truncation needed, consistent with either rule)
- `generateSku('Écusson brodé', 'M', 'White')` → `'ECUSSONB-M-WHI'` (plain truncation of both tokens, consistent with either rule)

The task-3 action block independently repeats the same `BLK`-not-`BLA` expectation twice more (`TSHIRT-S-BLK`, `TSHIRT-M-BLK`), ruling out a one-off typo. Testing the hypothesis "if the cleaned token's last character is a vowel, truncate plainly; if it's a consonant (or digit), preserve that last character and cut just before it" against all four data points, it matches every one exactly (`BLACK`→`BLK`, `WHITE`→`WHI`, `ECUSSONBRODE`→`ECUSSONB`). Implemented that rule and documented the rationale in `sku.ts`'s leading comment. This is Claude's Discretion under D-13, resolved in favor of matching the plan's own worked examples rather than its looser prose summary.

**2. Diacritic-stripping implementation avoids a literal `\u` regex escape.**
Multiple attempts to write `/[̀-ͯ]/g` as a regex literal in the file were corrupted in transit — sometimes landing as the raw Unicode combining characters, sometimes as a doubled backslash that would have silently changed the regex's meaning (turning it into a broad `0`-to-`\` ASCII range). Rather than risk a silently-wrong regex shipping to production, `stripDiacritics()` filters `Array.from(str)` by `codePointAt(0)` against the numeric range `0x0300`–`0x036f` (the standard "Combining Diacritical Marks" Unicode block), which needs no backslash-escape literal at all. Functionally identical to the regex approach; verified via the Écusson→Ecusson test case. The acceptance-criteria grep for diacritic-stripping evidence (`u0300`) is satisfied by the doc comment, which spells out the codepoint range in prose.
