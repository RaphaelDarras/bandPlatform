# Phase 06.1 Plan 02: SKU Uniqueness Guard Summary

**Application-level `findSkuClash` guard added to `api/routes/products.js`, rejecting duplicate SKUs with 409 on both product creation and add-variant, with tests pinning the `PUT` `$pull` footgun in both directions.**

## Performance

- **Duration:** ~15 min
- **Completed:** 2026-08-06
- **Tasks:** 2/2 completed
- **Files modified:** 3

## Accomplishments
- `findSkuClash(skus, excludeProductId)` — a module-level helper in `api/routes/products.js` — detects both in-payload duplicate SKUs and cross-product SKU collisions via a plain `Product.findOne({ 'variants.sku': { $in: skus } })` lookup, with zero new indexes (D-14's explicit "no unique index" requirement, since `variants.sku` is an embedded-array field where a unique multikey index would fail to build against any pre-existing duplicate data).
- `POST /` now rejects a colliding SKU with 409 before `Product.create(req.body)` ever runs; the unfiltered `req.body` passthrough that makes D-11's one-step opening-stock create work is completely unchanged.
- `PUT /:id`'s "add new variant" branch computes only the genuinely-new SKUs (payload SKUs absent from the product's existing set) and runs the same guard, excluding the product being edited from the lookup. The guard executes before the `$pull` that removes omitted variants and before the `$set`/`$push` update loop, so a 409 response guarantees zero database writes occurred — closing the partial-application half of the D-17 footgun without touching the footgun's accepted destructive-omission behavior itself.
- Six new test cases across `products.test.js` and `products-put.test.js` pin: cross-product SKU clash 409 on create, in-payload duplicate SKU 409 on create (short-circuits before any `findOne` call), D-11 opening-stock passthrough (`variants[0].stock === 7` reaches `Product.create`), new-variant SKU clash 409 on `PUT` with zero `updateOne` calls, `$pull` removing nothing when the full variant array is sent, and `$pull` firing exactly once when an existing SKU is omitted.
