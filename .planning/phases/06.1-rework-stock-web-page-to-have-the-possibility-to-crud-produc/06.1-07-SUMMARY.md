# Phase 06.1 Plan 07: Add Variant Panel Summary

**AddVariantPanel component performing the D-17 full-variant-array PUT then the D-18 chained stock write, with a SKU-naming partial-failure hand-off instead of a generic error**

## Performance

- **Duration:** ~25 min
- **Completed:** 2026-08-07
- **Tasks:** 2 completed
- **Files modified:** 2 (both created)

## Accomplishments
- Built `AddVariantPanel`, reusing the shared `VariantGenerator` (D-19) with no size/colour/SKU logic duplicated
- Implemented the D-17 footgun-safe payload: every call to `putProductVariants` spreads all of `existingVariants` before the new rows, so the server's `$pull`-missing-SKUs behaviour never deletes other variants
- Implemented the D-18 chained write: `batchAdjustStock` fires only for rows with a non-zero opening count, and a failure there calls `onPartialFailure(seeds, message)` carrying the *intended* stock count (never 0) instead of rendering a generic error
- Wrote 8 tests pinning both riskiest behaviours: the full-array length/membership assertion, the happy chain, the no-quantity shortcut, first-write failure (row preserved, nothing created), the D-18 hand-off (intended count survives, no generic "something went wrong" text), and both `AuthExpiredError` paths (D-30)
