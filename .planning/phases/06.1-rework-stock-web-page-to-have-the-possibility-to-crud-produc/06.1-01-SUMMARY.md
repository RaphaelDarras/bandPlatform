# Phase 06.1 Plan 01: Batch stock transaction + includeInactive Summary

**Transactional `POST /api/inventory/restock/batch` (Mongoose `session.withTransaction()`) plus `includeInactive`/`active` on `GET /api/inventory/stock`, proven all-or-nothing by a new `MongoMemoryReplSet`-backed Jest suite.**

## Accomplishments
- New `POST /api/inventory/restock/batch` endpoint applies N stock adjustments as one atomic Mongo transaction — a mid-batch failure leaves every variant's stock unchanged and writes zero `InventoryAdjustment` records (D-06), machine-verified against a real in-memory replica set (not mocked Mongoose, which cannot model transaction abort).
- `GET /api/inventory/stock` gained `?includeInactive=true` and an `active` field per product, scoped exclusively to this authenticated route — `GET /api/products` (public, mobile-POS-facing) is untouched (D-24).
- First use of `MongoMemoryReplSet` in this repo, establishing the pattern any future transaction-exercising test must follow (the existing `MongoMemoryServer`-based tests cannot run transactions).
